Transcendence directory map
===========================

Purpose:
- Transcendence is a research workbench for model, strategy, gate, replay, and audit flows.
- Keep reusable source, reproducible workflow configs, tests, and a small curated evidence set here.
- Store generated runs in MLflow or another external artifact store, not beside source files.

Active source and configs kept at root:
- *.py research entry scripts
- 4 primary workflow_config_*.yaml entry configs kept at root for direct script compatibility
- sota_snapshot.json because active support/search scripts read it directly

Root script role split:
- thin wrapper entry scripts remain at root for command compatibility with archived summaries, snapshots, and prior run notes
- substantial logic lives under support/, strategy/, and model/
- regime_switch_stability_eval.py is a notable root-level wrapper with extra post-processing logic and therefore remains visible at root

Subdirectories:
- support/ helper scripts and supporting research utilities
- strategy/ strategy-layer experiments
- model/ model-layer implementations and reproducible runners
- configs/ organized, reusable workflow configs
- configs/workflows/regime_horizon/variants/ compatibility workflows still referenced by tests or live scripts
- configs/workflows/transcendence/ retained CPU/GPU ensemble workflows with active test coverage
- configs/workflows/ensemble/ canonical ensemble workflows
- reports/curated/ preserved high-value leaderboard / gate / round-summary references

Current high-signal references:
- MLFLOW_RETENTION.txt
- model/run_purged_oof_stacking.py
- reports/curated/regime_switch_stability_reverify_gate_ready_summary_7406e470_20260527T093714Z.json
- reports/curated/portfolio_innov_ext_i10_summary_7406e470_20260519T122816Z.json

Retention policy:
- Keep a workflow when active source, tests, or production scripts reference it, or when it is the canonical reproducible config for a retained model direction.
- Keep model code when it provides a tested reusable capability or backs a retained workflow.
- Keep only curated reports that support a current benchmark or gate decision.
- Do not commit timestamped run configs, smoke-test outputs, caches, logs, or raw MLflow artifacts.
- Treat MLFLOW_RETENTION.txt as the allowlist for local MLflow cleanup.
- Remove failed directions once a stronger retained approach supersedes them and no stable consumer remains.

Compatibility notes:
- Root keeps the small set of configs still directly hard-referenced by code paths.
- Many root-level *.py files are intentionally thin wrappers that forward to support/ implementations for compatibility with old commands and archived run records.
- Read-mostly benchmark result references were moved into reports/curated/ to keep the root focused on runnable entry points.
- Root wrappers are intentionally preserved because historical summaries and snapshot metadata still reference `examples/benchmarks/Transcendence/*.py` command paths.
- Model-layer full verification artifacts after 2026-05-28 live under repo-level artifacts/verifier_v17-v22.
